## State of HTML results

The [2026 State of HTML survey results](https://2026.stateofhtml.com/) are out, and I’ve been reading through them with much interest. I do that every year, but this year especially because I got asked to write the conclusion!

![](https://kilianvalkhof.com/wp-content/uploads/2026.stateofhtml.com_en-US-State-of-HTML-2026-2026-11-18-12.14.04.png)

What makes the State of HTML interesting is that it’s more broadly the state of the “platform”. Much of browser behavior is mediated through HTML, and increasingly that includes things that aren’t purely for rendering user-facing content. Things like speculationrules and fetchpriority, when used well, aren’t meant to be noticed.

The increasing push to declarative APIs for the web is also prevalent in the survey results. That’s again not an HTML only thing (in CSS, anchoring is a good example) but features like customizable select and invoker commands replace many lines of imperative code with simple declarations.

The last ‘trend’ I see is an every increasing awareness of accessibility. HTML and accessibility are very much intertwined. With features getting declarative equivalents, the “name, role, value” aspects also get co-located, making it easier to get them right.

## One page, two readers.Every page has a Markdown twin for agents to read.

[Blume for agents](https://useblume.dev/agents)

llms.txt

An index and the full corpus in `llms-full.txt`, rebuilt on every build.

Markdown at every URL

A Markdown twin of every page at its `.md` URL, with `Accept: text/markdown` negotiation on Vercel and Cloudflare server builds.

An MCP server

Opt-in tools that let coding agents search and read your docs directly.

Agent skills

Point Blume at your skills and it publishes them where agents look.

## Batteries included.No plugins to install, no services to wire up.

[Read the docs](https://useblume.dev/docs)

## Markdown with superpowers.No imports, no JSX to manage.

Directives become callouts.

`:::tip`, `:::warning`, and friends render as styled callouts, with nothing to import.

Package names become install tabs.

A `package-install` fence renders npm, pnpm, yarn, bun, nub, and aube commands as tabs.

Code, highlighted.

Shiki highlights at build time, with titles, line numbers, highlighting, and TypeScript-to-JavaScript tabs.

Math and diagrams.

KaTeX math renders at build time with no client JavaScript, and Mermaid diagrams load only on the pages that draw them.

[See the full syntax](https://useblume.dev/docs/content/syntax)

## Content from anywhere.Mix local files, remote repos, and your CMS in one site.

A folder is a site.

Local Markdown and MDX need no configuration at all.

Remote repositories.

`mdxRemote()` pulls MDX from another GitHub repository at build time.

Headless CMSs.

Notion, Sanity, Contentful, Payload, and Strapi over their APIs, plus Obsidian vaults.

Anything else.

A `custom()` adapter brings any backend without its SDK touching core.

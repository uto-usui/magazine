## 今回のテーマ「照」に込めた思い

—— 今回のテーマは「照」です。どういう思いが込められているのでしょうか。

**ydah：**「照」というテーマには、いろいろな意味を込めています。

ひとつは、「見えない構造を明らかにする」という意味合いです。複雑なシステムの裏側や、アーキテクチャの背景、設計思想などに光を当てるようなお話ですね。また、関西の地域Ruby会議では、伝統的に低レイヤや電子工作のトークが多いんです。なので、表面からは見えない低レイヤの仕組みをひもとくことや、文字どおり LED を使って物理的に「照らす」ことも、このテーマに含まれています。

—— かなり幅広く解釈できるテーマなんですね。

**ydah：**はい。他にも、Ruby がきっかけで新しいチャレンジが生まれたというエピソードも「照」だと考えています。Ruby と出会って自分の新しい道や未来が照らされたり、未知の領域にスポットライトを当てたり、自分が作ったものに光を当てたり。そうした参加者それぞれの「多様な光」を持ち寄って、いろいろな角度から Ruby という言語を照らし出す。そんなカンファレンスにしたいと思っています。

### 11:20〜11:40 「Project Naraku 外伝 —— レールロード図で照らすOnigmoのバグ」 shimokawa さん

—— 続いて、[shimokawa](https://github.com/aim2bpg) さんの「Project Naraku 外伝 —— レールロード図で照らすOnigmoのバグ」です。

**ydah：**Ruby の正規表現エンジンに関するお話です。RubyKaigi 2026 で発表された Ruby 専用正規表現エンジン [Naraku](https://github.com/makenowjust/naraku) は、現在の Ruby で使われている正規表現エンジン [Onigmo](https://github.com/k-takata/Onigmo) の問題を照らし出しました。その問題を、正規表現の構造を線路の分岐のような図で表すレールロード図のエディタ [Rubree](https://github.com/aim2bpg/rubree) で可視化する構成だと理解しています。

たとえば入口として、`/ss/i` が `ß` にマッチするという話があります。`/i` は単なる ASCII の大文字小文字変換ではなく、Unicode の多対多の変換まで扱っているので、こういうことが起きます。そのうえで、図の上では対称に見えるのに実際の挙動は対称にならないパターンを紹介していただけると思っています。なぜそうなるのかは、当日のお楽しみにしておきましょう。

—— 普段使っている正規表現の下に、そんな世界があるんですね。

**ydah：**そうなんです。Naraku がなぜ必要なのかを、抽象的な説明ではなく具体的な事例と可視化を通して理解できそうなのが、このトークの良いところだと思っています。RubyKaigi 2026 で Naraku に興味を持った方が、もう一歩踏み込むきっかけにもなると思います。

### 13:10〜13:30 「torikago - Ruby::Boxで照らすモジュラモノリスの実行境界」 nori さん

—— 午後最初のセッションは、弊社 SmartHR の [nori](https://github.com/se4weed) さんの「torikago - Ruby::Boxで照らすモジュラモノリスの実行境界」です。

**ydah：**Rails のモジュラモノリスにおける実行時の境界についてのトークです。大規模な Rails アプリケーションでは、[packwerk](https://github.com/Shopify/packwerk) や [Rails::Engine](https://guides.rubyonrails.org/engines.html) を使ってドメインごとに module を分け、構造上の境界を作るアプローチがあります。ただ、module を分けても実行時には同じ Ruby VM を共有しているので、定数参照、monkey patch、暗黙の結合といった問題は残ります。そこで、ひとつの Ruby VM の中に独立した実行空間を作れる Ruby 4.0 の実験的機能 Ruby::Box を使い、module ごとの実行境界を扱う gem として [torikago](https://github.com/se4weed/torikago) を紹介していただけるそうです。

—— 実験的機能を実際に使うとなると、一筋縄ではいかない部分もありそうですね。

**ydah：**そこも見どころだと思っています。Ruby::Box との相性が難しい gem があることや、性能面の課題など、何がまだ難しいのかも率直に共有していただけるそうです。普段は見えにくいモジュラモノリスの実行時の境界に光を当てるトークになりそうです。

### 15:20〜15:40 「Can you see? I'm GC」 yhara さん

—— 続いて、[yhara](https://github.com/yhara) さんの「Can you see? I'm GC」です。タイトルが印象的ですね。

**ydah：**Ruby 処理系にとって欠かせない構成要素であるにもかかわらず、日ごろあまり意識されない GC（ガベージコレクション）に光を当てるトークです。Ruby を書いていると、メモリ管理の多くは GC が引き受けてくれます。おかげで私たちはアプリケーションのロジックに集中できますが、逆に GC が何をしているのかは見えづらいですよね。今回は、Ruby 3.4 から実験的に導入された、GC の実装を差し替えられる [Modular GC](https://www.ruby-lang.org/en/news/2024/12/25/ruby-3-4-0-released/) の機構を使って、カスタムのGCを作った話が聞けるそうです。

—— 普段任せきりにしている GC が、裏でどれだけのことをやっているのか、気になってきますね。

**ydah：**そうなんです。GC の大変さを実際に体験できる仕掛けも用意されていると聞いています。GC が何を見て、どのようにオブジェクトをたどり、メモリを回収しているのかを、可視化や体験を通じて理解できるトークになりそうです。タイトルの通り、GC をただ知識として学ぶだけでなく、自分ごととして感じられる時間になると思います。また、yhara さんは[中学生のころ、大津市立の中学校の科学部でプログラミングを学ばれたそう](https://rubykansai.github.io/kansai09/speakers)です。プログラミングの原点である大津で開催する関西Ruby会議で、トークをしていただけることに、不思議な縁と嬉しさを感じています。

### 15:50〜16:10 「VMとAOTコンパイラ開発で照らす8Bit機の世界」 Yuji Yokoo さん

—— 公募セッションの最後は、[Yuji Yokoo](https://github.com/yujiyokoo) さんの「VMとAOTコンパイラ開発で照らす8Bit機の世界」です。

**ydah：**8bit機で Ruby を動かすお話です。Yuji さんは「ゲーム機で Ruby を動かす」というテーマでプロジェクトを続けている方で、今回は [Z80](https://ja.wikipedia.org/wiki/Z80) という 8bit CPU をターゲットに、組み込み向け軽量 Ruby 実装 [mruby](https://mruby.org/) の VM と、AOT（Ahead-Of-Time）コンパイラの話を扱っていただけるそうです。VM は実行時に1命令ずつ解釈する方式、AOT コンパイラは事前にコンパイルしておく方式で、対照的な2つのアプローチを同じ題材で見られるのが見どころです。現段階では[セガのマスターシステム](https://ja.wikipedia.org/wiki/%E3%82%BB%E3%82%AC%E3%83%BB%E3%83%9E%E3%82%B9%E3%82%BF%E3%83%BC%E3%82%B7%E3%82%B9%E3%83%86%E3%83%A0)をサポートしているそうです。

—— 普段の Web 開発とはかなり違う世界ですね。

**ydah：**まったく違うと思います。8bit機には、メモリ、CPU、開発環境など、現代の開発とは違う制約があります。古いゲーム機に触れたことがない人に向けて、一般的な開発環境とは違う環境やプロセスを紹介する発表にしたいと聞いています。普段あまり触れない限られた世界に Ruby で光を当てることで、Ruby の別の顔が見えてくる。公募セッションの締めくくりとしても、印象に残る内容になると思います。

## The carry-over toggle

[

![UX Movement](https://miro.medium.com/v2/resize:fill:32:32/1*0hVXTjSwlD8Kje1OlclpDg.png)



](https://uxmovement.medium.com/?source=post_page---byline--dcc8087a7ea7-----------------------------------------)

Does your dashboard allow users to create new items? If so, they may be exerting too much physical and cognitive effort filling out the creation form.

For example, imagine how much work a user does when they create a new project every week. Each time, they have to invite the same team members and select the same settings. That’s not only extra thinking, but also extra clicks.

A good UX doesn’t force users to rebuild everything from scratch. Instead, it reduces the cognitive load with time-saving features that do the work for them. That’s what you need to do so your users don’t have to make the same decisions and selections all over again.

![](https://miro.medium.com/v2/resize:fit:700/0*mb-GZtwUekV8OJkq.png)

The design solution is to add a carry-over toggle that reuses the settings from their last project. Settings that rarely change between projects, like team members and notification preferences, only need to be entered once when a carry-over toggle is available. Without it, users have to recall and reselect the same options every single time they start something new.

Turn the toggle on, and all fields collapse into a single confirmation: a few teammate avatars and one line of text stating the carried-over settings. Turn the toggle off, and it brings back all the fields for users to fill out again.

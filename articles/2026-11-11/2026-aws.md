こんにちは、株式会社WinTicket でバックエンドとインフラを担当している茨木啓瑚（[@oyasumi\_pants](https://x.com/oyasumi_pants)）です。

本記事では、2026年度のサイバーエージェント新卒研修として実施した「AWS インフラハンズオン」について、その背景と内容の一部を紹介します。研修で使用したスライドとハンズオンのコードもあわせて公開します。どちらも、社外の方がご自身の AWS アカウントで試せる形に整えています。

## 昨年度の振り返り

私がこの研修を担当するのは今年で 2 回目です。昨年度は、新卒研修の後半にあるチーム開発でインフラ構築に困らないようにすることを目的に、3 時間で AWS の主要サービスの座学と、Terraform を使った構築ハンズオンを行いました。

昨年度に難しさを感じたのは、受講者の職種の幅です。バックエンドだけでなく、機械学習・データ、Web フロントエンド、ネイティブ、ゲームクライアントと職種はさまざまで、全員に同じ到達点を求めるのは現実的ではありませんでした。とはいえ、AI を活用した開発が広がる中で、エンジニアには職種を越えて手を動かす力が求められています。そこで今年度は、職種ごとに目指してほしい状態を明確にしたうえで研修を進めることにしました。

![本研修のゴール](https://developers.cyberagent.co.jp/blog/wp-content/uploads/2026/11/aws-handson-2026-slide007.png)

また、昨年度の受講者アンケートでは「AWS のリソースを網羅的に扱ってもらえたのがよかった」という声を多くいただきました。今年度はこの網羅性をさらに強化しています。

今年度も、全員に共通して持ち帰ってほしいものは「AWS サービスに対する知識のインデックス」としました。研修の後にはチーム開発が控えているので、作りたい機能に対して「このサービスを使えばいい」とすぐに思い浮かぶこと、迷ったときにこの資料を開けばひとまず答えが見つかることを重視しています。

章立てや説明の構成は昨年度から大きくは変えず、内容の更新とハンズオン環境の整備に力を入れました。

![研修の章立て](https://developers.cyberagent.co.jp/blog/wp-content/uploads/2026/11/aws-handson-2026-slide002.png)

## セットアップ

AWS CLI、Terraform、Docker のインストールと動作確認は、研修当日までに各自で進めてもらう形にしました。当日は確認だけで済むので、3 時間の多くを座学とハンズオンに充てられます。

## AWS リソースに触れる

Network、Compute、Database、Security、Storage、Application Integration、Management、Developer Tools、AI の順に、34 のサービスを紹介する座学パートです。昨年度の資料は 2019 年から 2023 年の AWS Black Belt を参照している箇所が多かったため、すべてのサービスについて最新のアップデートを確認し、古い情報を更新しました。

研修当日は 3 時間と限られているため、口頭で詳しく説明したのはネットワークの章に絞りました。それ以外の章は、ハンズオンの環境構築に必要なリソースを把握するための辞書として使ってもらうことを想定しています。研修のあとでもいつでも見返せることを意識して作っています。

説明は「○○とは」から図解に進み、最後に全体構成図に戻って今どこの話をしているかを示す、という流れで進めます。インフラに馴染みのない受講者でもイメージしやすいように、身近なお店に例えた説明を口頭で補足しました。たとえばネットワークの章では、VPC をお店を建てる土地、サブネットを入れる人が異なる区画、Route Table を店内の案内標識として説明しています。

## Terraform ハンズオン

init、plan、apply、destroy の基本操作と、tfstate、module、変数を扱います。コマンドを覚えること以上に、「なぜ IaC を使うのか」を最初に押さえることを大切にしました。

![IaC（Infrastructure as Code）とは？](https://developers.cyberagent.co.jp/blog/wp-content/uploads/2026/11/aws-handson-2026-slide155.png)

ハンズオンでは nginx コンテナを題材に、Scope から Apply までのライフサイクルを一通り体験します。

![Terraform のライフサイクル](https://developers.cyberagent.co.jp/blog/wp-content/uploads/2026/11/aws-handson-2026-slide157.png)

そのうえで、構築したリソースの状態を追跡する tfstate や、再利用できるコードのまとまりである module の考え方を、図で整理しながら説明しました。

![tfstate について](https://developers.cyberagent.co.jp/blog/wp-content/uploads/2026/11/aws-handson-2026-slide170.png)

![Terraform module について](https://developers.cyberagent.co.jp/blog/wp-content/uploads/2026/11/aws-handson-2026-slide172.png)

## AWS ハンズオン

Go で書いた書籍管理 API「Bookshelf」を ECS Fargate 上で動かし、Aurora MySQL と CloudFront をつないで API を呼び出すところまでを構築します。構成には、サイバーエージェント社内でも広く採用されているリソースを選びました。

![Bookshelf の構成図](https://developers.cyberagent.co.jp/blog/wp-content/uploads/2026/11/aws-handson-2026-slide187.png)

構築は Network、Database、Operation、ECR、ECS、CloudFront の 6 つの module に分け、1 つずつ apply していきます。各 module の前には、作るリソースを図でグルーピングしてから Terraform のコードに対応づけるスライドを挟み、AWS リソース同士の関係をつかみながら進められるようにしました。

![Network module を Terraform に起こすと](https://developers.cyberagent.co.jp/blog/wp-content/uploads/2026/11/aws-handson-2026-slide195.png)

module 間の依存関係も図にしているので、ある module の output が別の module のどこで使われるのかを追えます。

![module 間の依存関係](https://developers.cyberagent.co.jp/blog/wp-content/uploads/2026/11/aws-handson-2026-slide249.png)

コンテナイメージのタグは受講者のユーザー名をもとにして、受講者同士でリソースが競合しないようにしました。実行環境は、Apple Silicon の Mac が多数派になったことに合わせて ECS Fargate を ARM64 に揃え、ローカルでのビルドと本番の実行環境を一致させています。最後はブラウザから API を呼び出し、登録した書籍データが返ってくることを確かめて完了です。

![ブラウザから API の動作を確認](https://developers.cyberagent.co.jp/blog/wp-content/uploads/2026/11/aws-handson-2026-slide268.png)

ハンズオンのコードは GitHub で公開しています。社内版では Route 53 と ACM でチームごとのサブドメインを使っていましたが、公開版はドメインを用意しなくても試せるように、CloudFront 経由の HTTPS に変えています。

-   [CyberAgentHack/getting-started-with-terraform](https://github.com/CyberAgentHack/getting-started-with-terraform)（Terraform ハンズオン）
-   [CyberAgentHack/aws-terraform-handson](https://github.com/CyberAgentHack/aws-terraform-handson)（AWS ハンズオン）

公開版は、ご自身の AWS アカウントで試せるように、IAM ユーザーの準備と tfstate 用の S3 バケットを作る手順を追加しています。NAT Gateway や Aurora、ALB は起動している間ずっと料金がかかるので、試し終えたらスライド後半の手順でリソースを削除してください。

## 受講後のアンケートから

受講者 65 名の回答を集計しました。職種の内訳は、バックエンドと機械学習・データがそれぞれ 22 名、ネイティブ 7 名、Web フロントエンド 6 名、ゲームクライアント 5 名などです。

全体満足度は 5 段階で 4 以上が 91% でした。パート別ではセットアップに 5 をつけた人が 50 名と最も多くなりました。研修前と比べて AWS やインフラへの興味が高まったと答えた人（4 以上）は 88% です。

よかった点として、次のような声が寄せられました。

-   「講義では時間の関係で飛ばしたページも、配布資料の各サービスの詳細が理解の助けになった」（機械学習・データ）
-   「普段インフラは触らないが、飲食店の例えでなんとなくのイメージを持てた」（ネイティブ）
-   「インフラ構成図で、今からどこを Terraform で作るのかが分かった」（Web フロントエンド）
-   「AWS のインフラ研修でチーム開発に自信がつき、インフラがより好きになった」（バックエンド）
-   「スライドのリソース紹介パートが非常に分かりやすい上に、網羅性が高く、とてもありがたかった」（機械学習・データ）
-   「ちょっとだけインフラ理解できた。Terraform すげ〜〜」（ゲームクライアント）

「リキャリア組なので新卒 1 年目のときにこのハンズオンを受けたかった」「ここまでの新卒研修の講義パートで一番満足度が高かった」というコメントもあり、大きな励みになりました。

一方で、課題も見えました。「コマンドは実行できたが、何のための操作かが追いつかずコピペになった」という声も複数あり、チーム開発で AWS を使う自信がついたと答えた人（4 以上）は 58% にとどまりました。

この声を受けて、公開版では apply のあとにマネジメントコンソールで作成されたリソースを確認するスライドを 14 枚追加しました。コマンドの結果を画面で確かめながら進めることで、いま何を作っているのかを追いやすくしています。

![マネジメントコンソールで NAT Gateway へのルートを確認](https://developers.cyberagent.co.jp/blog/wp-content/uploads/2026/11/aws-handson-2026-slide201.png)

## おわりに

今年度の研修では、昨年度好評だった網羅性をベースに、最新のサービスと AI 関連の内容を加えて資料をアップデートしました。

この研修の内容は、職種を問わずエンジニア全員がインフラについて会話できるようになるうえで、ちょうどよい水準だと考えています。資料は AWS の公式資料を広く参照しているので、AWS を学び始めるときに最初に開く資料として使っていただけると嬉しいです。

来年度は、AI を使った開発が前提になっていくことを踏まえ、そこに向けたアプローチも取り入れていきたいと考えています。本記事と資料が、これから AWS に触れる皆さんにとって、インフラを楽しみながら学ぶきっかけになれば幸いです。

[Introducing: React Best Practices](https://react.statuscode.com/link/179398/web "vercel.com") — The Vercel team has boiled down _“10+ years of React and Next.js optimization knowledge”_ into [a suite of Markdown files](https://react.statuscode.com/link/179399/web) intended for use by coding agents like Claude Code and [OpenCode](https://react.statuscode.com/link/179400/web), though you can just as easily read them yourself. The goal is to allow such agents to write better React code without needless handholding.

Ding and Qu (Vercel)

[How to 'Steal' Any React Component](https://react.statuscode.com/link/179401/web "fant.io") — This is more _‘reconstructing a component based upon a lot of clues’_, but is nonetheless an interesting look at how to reproduce a component from a production React app without the original source code, using React’s internal data structures (via [Fiber](https://react.statuscode.com/link/179402/web)) and LLMs to reconstruct things.

David Fant

**IN BRIEF:**

-   Microsoft's [_Aspire_](https://react.statuscode.com/link/179405/web) app orchestration framework now [treats JavaScript as a first-class citizen](https://react.statuscode.com/link/179406/web) meaning you can now use it to build and deploy full React apps, complete with Vite.

-   Cursor, the popular agent-based development tool, [slipped a note into a recent developer log](https://react.statuscode.com/link/179409/web) that it's experimenting with a migration from Solid to React and may make the switch in a future release.
    
-   [An interview with David Haz](https://react.statuscode.com/link/179410/web), the creator of [React Bits](https://react.statuscode.com/link/179411/web), a suite of animation-focused components.
    

[`useOptimistic` Won't Save You](https://react.statuscode.com/link/179412/web "www.columkelly.com") — React 19’s [useOptimistic](https://react.statuscode.com/link/179413/web) hook is supposed to make optimistic UI updates simple, but in this detailed walkthrough, Colum shows that many problems still lurk. His takeaway: these APIs are designed for framework authors, and the rest of us should probably let our frameworks handle the complexity.

Colum Kelly

[Building Type-Safe Compound Components](https://react.statuscode.com/link/179414/web "tkdodo.eu") — _“I think compound components are a really good design-pattern when building component libraries. They give consumers flexibility in how components are composed, without forcing every variation into a single, prop-heavy API.”_

Dominik Dorfmeister

[Deploy React on Any Cloud](https://react.statuscode.com/link/179415/web "www.cloud66.com") — Cloud 66 for static sites creates a Netlify experience on your own cloud and save up to 60%.

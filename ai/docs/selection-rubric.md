# 記事の選び方

ニュースレター（`/create-newsletter`、`/create-newsletter-auto`）とピックアップ（`curate-articles`）で記事を選ぶときの基準。

## 読者

デザインと実装のあいだで仕事をする人。UX エンジニア、デザインエンジニア、フロントエンドエンジニア、デザインシステムの担当者など。
「この記事を読んで、来週の仕事で何か変わるか」を基準に考える。

## 1. 足切り

次のどれかに当たる記事は採点せずに外す。

- **本文が取れていない**: 抜粋だけ、有料部分で切れている、数行しかない（取得の失敗でも、ページがもともと短くても同じ）。中身を判断できないので選ばない
- **お知らせだけの記事**: リリースノート、changelog、イベント告知、採用、製品の宣伝。ただし「なぜそう設計したか」か「計測の結果」が書いてあるものは採点に回す。新機能の紹介や公式どおりの設定手順だけなら外す
- **リンク集・ダイジェスト号**: 他サイトの記事を集めて短く紹介する号（React Status、A11y Weekly などの週刊号）。他人の記事の要約で点を取ってしまうので外す。中に気になる一次記事があれば `note` に URL を書いておく
- **同じ出来事の重複**: 同じ発表やリリースについての記事は 1 本にする。一次情報に近いほう（発表元、著者本人）を、どちらも一次なら情報が多いほうを残す。主張が似ているだけの別々の記事は重複ではない

## 2. 採点

4 つの観点をそれぞれ 0〜2 点でつける（合計 0〜8 点）。迷ったら低いほうにする。

### A. 読者の仕事との近さ

| 点 | 目安 |
|---|---|
| 2 | 体験と実装の両方にまたがる。例: アクセシビリティの実装、デザインシステムの運用、操作感とパフォーマンス、UI の状態設計、デザインとコードの受け渡し |
| 1 | どちらか片方に深い。例: CSS の新機能の解説、ユーザーリサーチの手法 |
| 0 | どちらにも当たらない。例: インフラ、バックエンドだけの話、組織論や経営の一般論 |

### B. 持ち帰れるもの

| 点 | 目安 |
|---|---|
| 2 | 手法・パターン・判断基準が、どんな条件で使えるかまで書いてある |
| 1 | 考え方や一般的な助言はあるが、条件や手順まではない |
| 0 | ニュースや感想だけで、読者が使えるものがない |

### C. 根拠

| 点 | 目安 |
|---|---|
| 2 | 計測（数字）、条件をそろえた比較、調査、本番での事例がある（失敗談を含む） |
| 1 | 書き手が実際に作ったり運用したりした経験にもとづく話 |
| 0 | 主張だけ、または仮想の例だけで論じている |

### D. 新しさ

| 点 | 目安 |
|---|---|
| 2 | 新しい仕様や技術、新しい調査結果、定説への反論 |
| 1 | よく知られた話に、新しい切り口や事例を足している |
| 0 | 定番の知識の焼き直し |

## 採点に使わないもの

次のものは点数に入れない。入れると、中身と関係ない理由で有利不利が生まれる。

- **言語**: 日本語か英語かで加点も減点もしない
- **本文の長さ**: 長いだけで B や C が上がるわけではない。短くても判断基準がはっきり書いてあれば 2 点をつける
- **解説の書きやすさ**: 英語で読むのが重い、要約しにくい、は減点の理由にしない
- **書き手や会社の知名度**: 信頼できるかどうかは C の根拠で見る

## 3. 並べて選ぶ

1. A が 0 点の記事は、合計点にかかわらず選ばない。読者の仕事に関係ない記事は、ほかの点が高くても載せる意味がない
2. 残りを合計点の高い順に並べ、上から選ぶ
3. 同じフィードから 4 本以上にならないようにする。超えたら、そのフィードのいちばん低い記事を、次点の別フィードの記事と入れ替える（Sidebar のように他サイトの記事を 1 本ずつ流すフィードは対象外）
4. 同点の記事が並んだら、A の高いほうを選ぶ。それでも並んだら、選んだ記事がまだ少ないカテゴリのほうを選ぶ

選ぶ本数は各コマンドの指示に従う。

## 4. 記録

採点した結果を `newsletters/scores/<ニュースレターのファイル名>.tsv` に残す。足切りした記事も含め、対象の全記事を 1 行ずつ書く。
どの観点で選ばれやすいか、どのフィードの点が低いかを、あとから確かめるために使う。

```tsv
url	feed	lang	A	B	C	D	total	selected	note
https://example.com/a	Example Blog	en	2	2	1	1	6	yes
https://example.com/b	Vercel	en	-	-	-	-	-	no	足切り: changelog
```

- `lang` は `ja` か `en`（集計用。採点には使わない）
- 足切りした記事は点数の欄を `-` にして、`note` に理由を書く
- `note` は足切りの理由か、採点で迷った点だけを書く。空でよい

### 1. Software as Clay on the Wheel

**3行サマリー:**
- AIエージェントが自律的にコードを書く「Ralph Wiggumループ」パターンが注目を集めている
- テストが明確に定義されていれば、AIは人間の介入なしに数時間で複雑な実装を完了できる
- 成功のカギは「終了条件を正確に定義できるかどうか」にある

**詳細:**
Simon WillisonがGPT-5.2を使い、クリスマスツリーの飾り付けをしながら4.5時間でHTML5パーサーを完成させたというエピソードは象徴的です。9,200以上のテストをパスするこの実装は、「成功基準が明確なら自律性が機能する」という原則を示しています。Geoffrey Huntleyが提唱する「Ralph Wiggumループ」では、各イテレーションがクリーンな状態から開始し、仕様を読み、タスクを実装し、テストをパスすればGitにコミットするというサイクルを繰り返します。UXエンジニアにとっての示唆は、「仕様とテストの設計」がいっそう重要になるということでしょう。

📎 [記事を読む](https://dri.es/software-as-clay-on-the-wheel)

### 2. Beyond Generative: The Rise Of Agentic AI And User-Centric Design

**3行サマリー:**
- Agentic AIは指示を実行するだけでなく、目標を理解し計画を立て自律的に行動する
- 4段階の自律性レベル（観察・提案・計画・確認付き実行・完全自律）でユーザー体験を設計する
- 信頼の構築とエラー回復のためのUXリサーチ手法が新たに必要となる

**詳細:**
Victor Yoccoの記事は、Agentic AIのUXデザインに必要な新しいリサーチ手法を体系的に解説しています。とくに「Simulated Misbehavior Testing」という、AIが意図的に失敗するシナリオをテストする手法は興味深いアプローチです。AIが自律的に判断・行動する時代において、ユーザーの「メンタルモデル」と実際のシステム動作のギャップを埋めることが設計の核心となります。「Intervention Rate」や「Rollback Rate」といった新しい指標の提案も、実装時の参考になるでしょう。

📎 [記事を読む](https://smashingmagazine.com/2026/01/beyond-generative-rise-agentic-ai-user-centric-design/)

### 3. The Pulse #160: Why it's so dramatic that "writing code by hand is dead"

**3行サマリー:**
- LLMツールは「使えない」から「ほとんどのコードを書ける」レベルに数か月で進化した
- Microsoft社内では、ほとんどコードを書かなかったStaff+エンジニアやVPがAIツールの最大利用者に
- $120/年のSaaSを20分でLLMが置き換えた事例が、更新されないSaaSビジネスへの警鐘を鳴らす

**詳細:**
Assembly言語から高級言語への移行には何年もかかりましたが、LLMの進化は数か月単位で起きています。Gergely Oroszは、この変化の速さこそが「手書きコードの終焉」という主張を劇的にしていると指摘します。とくに注目すべきは、Microsoftの内部ダッシュボードが示す「シニアエンジニアほどAIツールを活用している」という事実です。彼らはコーディングだけでなく、計画立案や探索的な作業にもAIを使っています。

### 4. I Learned The First Rule of ARIA the Hard Way

**3行サマリー:**
- ARIAの第一のルールは「使わないこと」。セマンティックHTMLがすでに多くのアクセシビリティ機能を提供している
- `<button role="link">`のようなARIA属性の誤用は、キーボード操作とスクリーンリーダーの動作を壊す
- ARIAは「欠けている状態を伝える」ためのものであり、セマンティクスを上書きするためのものではない

**詳細:**
Hashim Quraishiの失敗談は、多くの開発者が陥りがちな罠を浮き彫りにしています。自動テストをパスし、キーボード操作も問題なく動作したのに、実際のスクリーンリーダーユーザーには使えなかったという経験です。原因は、ボタンに`role="link"`を追加したこと。スタイリングのためのフックとしてARIA属性を使うという発想自体が間違いでした。「DevToolsのAccessibilityパネルを確認する」という具体的なデバッグ手法も紹介されており、実践的な学びになります。

📎 [記事を読む](https://css-tricks.com/i-learned-the-first-rule-of-aria-the-hard-way/)

### 5. Masonry Layout is Now grid-lanes

**3行サマリー:**
- Masonryレイアウトは`display: grid-lanes`という新しい構文で標準化される方向に
- 2017年から続いた議論が2025年末にようやく決着し、構文が確定した
- 主要ブラウザはすでに実装作業を開始しており、今後の対応が期待される

**詳細:**
Pinterestスタイルのレイアウトを実現する「Masonry」は、W3Cで8年以上議論されてきた機能です。`display: masonry`、`staggered-grid`、`grid-pack`など多くの候補名が検討された末、`grid-lanes`に決定しました。Chrome/Edge、Safari、Firefoxの各チームがすでに実装作業を進めており、Gridの配置プロパティを再利用する形で実装されます。長年JavaScript ライブラリに頼ってきたレイアウトがネイティブCSSで実現できる日が近づいています。

📎 [記事を読む](https://css-tricks.com/masonry-layout-is-now-grid-lanes/)

### 6. text-decoration-inset is Like Padding for Text Decorations

**3行サマリー:**
- `text-decoration-inset`は下線などのテキスト装飾を両端からトリミングできる新プロパティ
- 従来の下線がコンテンツボックスの端まで伸びてしまう問題を解決する
- トランジションやアニメーションにも対応し、ホバーエフェクトの表現力が向上する

**詳細:**
デザイナー視点では気になっていた「下線が文字の端より少しはみ出る」問題が、ついにCSSで解決できるようになります。`text-decoration-inset: 0.076em 0.009em`のように左右で異なる値を設定でき、`em`単位を使えばフォントサイズに応じてスケールします。さらにアニメーションにも対応しているため、ホバー時に下線が伸縮するエフェクトもネイティブCSSで実装できます。現時点ではFirefox 146以降のみの対応ですが、ほかのブラウザへの展開が待たれます。

📎 [記事を読む](https://css-tricks.com/text-decoration-inset-is-like-padding-for-text-decorations/)

### 7. Responsive List of Avatars Using Modern CSS (Part 2)

**3行サマリー:**
- CSS `offset`プロパティを使い、円形に配置されたアバターリストをレスポンシブに実装する
- `sibling-index()`と`sibling-count()`関数で要素数に依存しない汎用的なコードを実現
- マスク処理とホバーアニメーションで、重なりを解消する洗練されたインタラクションを追加

**詳細:**
Temani Afifによるこのチュートリアルは、最新CSSの機能を駆使した実践的な実装例です。`offset-path: circle(180px)`で円形のパスを定義し、`offset-distance`で各要素の位置を計算します。`sibling-index()`と`sibling-count()`を組み合わせることで、要素数が変わっても自動的に等間隔配置になるのがポイントです。三角関数`sin()`、`cos()`を使ったマスク位置の計算など、数学的なアプローチも含まれますが、コピペで使えるコードスニペットとして価値があります。

📎 [記事を読む](https://css-tricks.com/responsive-list-of-avatars-using-modern-css-part-2/)

### 10. What's !important #1: Advent Calendars, CSS Wrapped, Web Platform Updates

### 12. Future CSS: :drag (and Maybe ::dragged-image?)

**3行サマリー:**
- ドラッグ中の要素をスタイリングする`:drag`疑似クラスがCSSWGで提案されている
- 現状はJavaScriptでクラスを切り替える必要があるが、CSSネイティブで実現できる可能性
- ドラッグプレビュー画像のスタイリング用`::drag-image`疑似要素の提案も

**詳細:**
Sunkanmi Fafoworaが提案している`:drag`疑似クラスは、ドラッグ&ドロップのUX実装を大幅に簡素化する可能性があります。現在は`dragstart`/`dragend`イベントでクラスを付け外しする必要がありますが、`.menu-bar:drag { opacity: 0.2; }`のようにCSSだけで記述できるようになります。著者は`::drag-image`疑似要素のissueも起票しており、CSSWGでの議論が予定されています。パフォーマンス、依存関係削減、メンテナンス性の観点からも魅力的な提案です。

📎 [記事を読む](https://css-tricks.com/future-css-drag-and-maybe-dragged-image/)

### 13. Toon Title Text Generator

**3行サマリー:**
- Andy Clarkeがカートゥーン風タイトルテキストを生成するツールをリリースした
- フォント、色、ストローク、シャドウなどを調整してCSSをエクスポートできる
- 各文字を個別にスタイリングするためのSplinter.jsも同時公開、アクセシビリティに配慮

**詳細:**
Andy Clarkeの新ツールは、遊び心のあるタイポグラフィを手軽に作成できます。CSSには`:nth-letter`がないため、文字単位のスタイリングには各文字を`<span>`で囲む必要がありますが、同時に公開されたSplinter.jsは`aria-label`と`aria-hidden`を適切に設定し、スクリーンリーダーへの配慮も忘れていません。GSAPのSplitTextと同様のアプローチですが、より軽量な選択肢として価値があります。

📎 [記事を読む](https://css-tricks.com/toon-title-text-generator/)

### 14. HTTP Archive 2025 Web Almanac

**3行サマリー:**
- 1,720万サイトを調査した2025年版Web Almanacが公開された
- 可変フォントの採用率が約40%に達し、もはや特別な技術ではなくなった
- ページサイズの中央値は2,362KBで、10年前から約3倍に膨らんでいる

**詳細:**
HTTP Archiveの年次レポートは、Webの現状を数字で把握するための必読資料です。`text-wrap: balance`（2.67%）や`text-wrap: pretty`（1.71%）の採用が始まっているものの、アクセシビリティ面では課題が残ります。WCAG色コントラスト基準を満たすサイトは30%のみ、フォーカスアウトラインを削除しているサイトは67%にのぼります。JavaScriptの中央値が697KBに達していることも、パフォーマンス改善の余地を示しています。

📎 [記事を読む](https://css-tricks.com/http-archive-2025-web-almanac/)

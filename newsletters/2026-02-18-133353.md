### [From Claude Code to Figma: Turning production code into editable Figma designs](https://www.figma.com/blog/introducing-claude-code-to-figma/)

> **出典**: Figma Blog | **公開日**: 2026-02-17 | **カテゴリ**: design

**3行まとめ**
- Claude Codeで構築したUIをFigmaキャンバスに取り込み、編集可能なフレームとして扱える新機能が登場した
- コードでの「収束的」な開発とキャンバスでの「発散的」な探索を行き来する、新しいワークフローを提案している
- Figma MCPサーバーを使えば、Figmaからコードへの逆方向の変換も可能で、双方向のラウンドトリップが実現する

**詳細解説**

Figmaが発表した「Claude Code to Figma」は、AIコーディング環境で生成したUIをFigmaの編集可能なデザインアーティファクトに変換する機能です。ブラウザで描画された状態をキャプチャし、Figmaのレイヤーとして取り込めます。

この機能が興味深いのは、コードとデザインの関係性を再定義しようとしている点です。従来の「デザイン→実装」という一方通行のワークフローではなく、コードからデザインへ、そしてまたコードへという双方向の流れを実現しています。Claude Codeのようなツールでプロトタイプをすばやく立ち上げ、それをFigmaキャンバスに持ち込んで複数のバリエーションを並べて比較し、チーム全体で方向性を議論できます。

UXエンジニアリングの視点でとくに注目したいのは、「コードは収束に強く、キャンバスは発散に強い」というFigmaの指摘です。実装を進めていると最初のバージョンがそのまま「唯一のバージョン」になりがちですが、キャンバスに持ち込めば複数案を視覚的に比較でき、より良い意思決定につながります。Figma Makeとの連携もあわせて、「どこから始めてもいい」というFluid Workflowの思想が一貫しています。

**詳細解説**

UXエンジニアリングにおいて、UIライブラリの「デフォルト」がアクセシビリティ要件を満たすとは限らないという教訓を、具体的なコードで示している点が価値のある記事です。デモサイトも公開されているので、実際にスクリーンリーダーで体験できます。

### [Interop 2026: Continuing to improve the web for developers](https://web.dev/blog/interop-2026?hl=en)

> **出典**: web.dev | **公開日**: 2026-02-12 | **カテゴリ**: web-standards

**3行まとめ**
- Apple、Google、Igalia、Microsoft、Mozillaが協力するInterop 2026が発表され、20以上のフォーカスエリアが設定された
- Anchor Positioning、Container Style Queries、View Transitionsなど開発者の要望が高い機能が多数含まれている
- アクセシビリティテスト、JPEG XL、モバイルテストなどの調査的取り組みも並行して進められる

**詳細解説**

Interop 2026は、主要ブラウザメーカーが協力してWeb標準の相互運用性を向上させる年次プロジェクトです。State of HTMLやState of CSSの調査結果をもとに、開発者がもっとも困っている機能を優先的に取り上げています。

UXエンジニアにとってとくに注目すべきフォーカスエリアがいくつかあります。**Anchor Positioning**はツールチップやポップオーバーの配置を宣言的に記述できる機能で、JavaScriptによるポジション計算が不要になります。**Scroll-driven Animations**はスクロール位置に連動したアニメーションをCSSだけで実現でき、パフォーマンスの良いインタラクションを作れます。**View Transitions**は前年からの継続で、今年はクロスドキュメント遷移にも対象が広がります。

新しく追加された**`contrast-color()`関数**は、指定した背景色に対してコントラスト比を保証する色を自動選択する機能で、アクセシビリティとデザインシステムの両面で有用です。**Media疑似クラス**（`:playing`、`:paused`など）は、オーディオ・ビデオ要素の状態に応じたスタイリングをCSSで表現可能にします。

調査的取り組みのなかでは「アクセシビリティテスト」が目を引きます。ブラウザ間で一貫したアクセシビリティツリーを生成する取り組みは、テスト自動化の信頼性向上につながるでしょう。

### [Reactive Depth: Building a Scroll-Driven 3D Image Tube with React Three Fiber](https://tympanus.net/codrops/2026/02/17/reactive-depth-building-a-scroll-driven-3d-image-tube-with-react-three-fiber/)

> **出典**: Codrops | **公開日**: 2026-02-17 | **カテゴリ**: design | **著者**: Matis Dene

**3行まとめ**
- React Three Fiberを使い、スクロール駆動で無限ループする3Dイメージチューブを構築するチュートリアル
- 頂点シェーダーによるジオメトリ変形、慣性ダンピング、ホバー時の時間減速など、物理的に一貫したモーションシステムを解説している
- パフォーマンス最適化としてReact stateを使わず、useRefとuseFrameのみでアニメーションループを制御している

**詳細解説**

Codropsによる、WebGLとReact Three Fiberを組み合わせた高度なインタラクティブ表現のチュートリアルです。単なるエフェクトの積み重ねではなく、「すべてが同じモーションシステムでつながっている」という設計思想が一貫しています。

技術的なポイントがいくつかあります。まず、`useRef`と`useFrame`のみでアニメーションを制御し、React stateによる再レンダリングを完全に排除しています。フレームごとの割り当て（allocation）もなく、安定したフレームレートを維持できる構成です。

シェーダーの解説も丁寧です。頂点シェーダーでは`smoothstep`を使ったエッジ変形とマウス追従の中心変形を組み合わせ、フラグメントシェーダーでは`fract()`と`fwidth()`によるアンチエイリアス付きの無限タイルグリッドを数学的に生成しています。

ホバー時に「回転速度を直接変更する」のではなく「時間そのものを減速させる」というアプローチが秀逸です。`dt`をスケールすることで、慣性やダンピングの物理モデルとの整合性を保ちながら、すべての動きが一貫して遅くなります。UXエンジニアがWebGLによる表現を学ぶ教材としても、設計思想を学ぶ素材としても価値があります。

- 「街灯の罠」とは、問題がある場所ではなくデータがある場所で解決策を探してしまう傾向を指す

UXリーダーやプロダクトマネージャーがAIプロジェクトのスプリント計画で「このプロジェクトの街灯バージョンは何か？」と問いかけるだけでも、チームの方向性が変わるでしょう。

### [New to the web platform in January](https://web.dev/blog/web-platform-01-2026?hl=en)

> **出典**: web.dev | **公開日**: 2026-01-30 | **カテゴリ**: web-standards

**3行まとめ**
- CSS Anchor PositioningがFirefox 147で対応し、Baseline Newly availableに到達した
- Chrome 144でTemporal APIが導入され、JavaScriptの日付処理が大幅に改善される
- `<geolocation>`要素やView Transition強化など、宣言的APIとインタラクション機能が充実した

**詳細解説**

2026年1月のWebプラットフォーム新機能をまとめた月次レポートです。Chrome 144とFirefox 147のリリースにより、複数の重要機能がBaseline入りしました。

**CSS Anchor Positioning**のBaseline Newly available到達は大きなニュースです。ツールチップやポップオーバーの配置をJavaScriptなしでCSSだけで表現できるようになり、Floating UIのようなライブラリの役割が変わる可能性があります。

**Temporal API**のChrome導入も注目です。Date objectの長年にわたる課題（タイムゾーン処理の不便さ、ミュータブルなAPI設計など）を根本から解決するもので、date-fnsやLuxonといったライブラリの代替となりえます。

**`<geolocation>`要素**は、位置情報の取得をJavaScript APIではなくHTML要素として宣言的に行えるようにする新しいアプローチです。パーミッション管理もブラウザが処理するため、開発者の負担が減り、ユーザー体験も改善されます。

**`::search-text`疑似要素**は、ブラウザのページ内検索結果のスタイルをカスタマイズできる機能で、コンテンツリッチなサイトでの検索体験を向上させる可能性を持っています。

- 予測と判断は補完関係にあり、AIは当面、現場の労働者を置き換えるよりも強化する方向に働く

**詳細解説**

経済学者Joshua Gansへのインタビューをもとにした記事で、AIを「計算統計学の進歩による予測コストの低下」と再定義する視点を提供しています。著書『Prediction Machines』の枠組みに基づき、AIを「知能」としてではなく「経済的ツール」として捉えるアプローチです。

空港のメタファーが秀逸です。公共ターミナルが大規模で複雑なのは、旅行者がいつ到着すればいいかわからないため、巨大な時間バッファを設け、その待ち時間をビジネスに変えているからです。プライベートターミナルは簡素で、より良い予測が不確実性を排除するため、バッファが不要になります。

この枠組みで組織を見ると、中間管理職の多くは「不確実性の吸収装置」として機能しています。AIによる予測精度の向上は、この層を平坦化します。一方で「予測と判断は代替ではなく補完関係にある」という指摘は重要です。AIが予測を担い、人間が判断を担うという役割分担が、少なくとも当面は続くとGansは見ています。

UXの視点では、「AIシステムを選定する人々は、本質的に自分の後継者を選んでいる」という指摘が印象的です。意思決定アーキテクチャの再設計こそが、真のAI変革であるという結論は、プロダクト設計にも通じます。

### [Toys, Crafts & Hobbies UX Benchmark: 5,500+ Performance Scores and 4,500+ Best Practice Examples](https://feeds.baymard.com/link/9825/17277775/toys-crafts-and-hobbies-ux-benchmark-2026)

> **出典**: Baymard Institute | **公開日**: 2026-02-17 | **カテゴリ**: ux-research | **著者**: Anders Nielsen

**3行まとめ**
- トイ・クラフト・ホビー業界のUXパフォーマンスは「凡庸」から「まあまあ」の範囲で、「良い」以上の評価を得たサイトはゼロだった
- 検索結果の絞り込み、商品比較、配送タイムラインの表示、カート管理など、意思決定の重要ポイントに体系的な弱さがある

# 記事キュレーション

newsletters/ の過去ニュースレターから記事を選定し、UXエンジニア向けのピックアップ記事を生成する。

## 引数

`$ARGUMENTS`: 対象期間を自然言語で指定（例: `今週`, `1月15日から20日`, `最新3回分`）。未指定時は直近2週間。

## 処理手順

### 1. 対象ニュースレターの特定

```bash
ls -1 newsletters/[0-9]*.md 2>/dev/null | sort -r
```

ファイル名 `YYYY-MM-DD-HHmmss.md` から日付を抽出し、`$ARGUMENTS` を解釈して日付範囲内のファイルを確定する。対象0件の場合はエラー終了。

### 2. 記事の抽出

対象ファイルをすべて読み込み、以下の情報を抽出:

- タイトル（`### [タイトル](URL)` 形式）
- メタ情報（`> **出典**: ... | **公開日**: ... | **カテゴリ**: ...`）
- 3行まとめ + 詳細解説

同一URLの記事は重複として除外する。

### 3. 記事の選定

**選定基準（優先度順）**:

1. **実践的価値** — 実務にすぐ活かせる知見・手法・パターンが含まれている
2. **技術的深さ** — 表面的なニュースではなく、なぜそうなるかの洞察がある
3. **UXエンジニアリングとの関連** — デザインとエンジニアリングの交差点にある、または片方に深い
4. **独自性** — ありふれた内容ではなく、読者の視野を広げる視点がある
5. **トレンド性** — 業界で注目されているトピックを扱っている

**除外するもの**:

- 風刺・ジョーク系 — おもしろいが実務価値が低い
- 内容が薄い記事 — 有料部分が取得できなかった、抜粋のみ等
- ニッチすぎる記事 — UXエンジニアより別の専門職向け
- 既知の定番知識の焼き直し — 新しい切り口がない場合

**選定数**: 12件以下→全て選定、13件以上→品質の高い10〜12件に絞る。

### 4. キュレーション記事の生成

**まず `references/editorial.md` を読み込むこと。** 編集テーマの決め方、記事の並び順、導入文・🐈‍⬛コメント・締め文の書き方の詳細ルールが書かれている。

**文体ルール**: `ai/docs/style-guide.md` を読み込み、漢字の開き閉じ・NGワード・冗長表現の回避など全ルールに従う。

#### 出力フォーマット

```markdown
# [期間を表すタイトル] UX Developer newsletter

**作成日**: YYYY-MM-DD
**対象期間**: [解釈した期間を自然な日本語で]

---

[冒頭の導入文: 2〜3文]

---

## [記事タイトル](元記事URL)

> **出典**: フィード名 | **公開日**: YYYY-MM-DD | **カテゴリ**: xxx

[元のニュースレターのまとめ]
- ポイント1
- ポイント2
- ポイント3

[元のニュースレターの詳細]

> 🐈‍⬛ : [編集者コメント]

---

（選定記事ごとに繰り返し）

[締めの文章]
```

### 5. ファイル出力

```bash
date "+%Y-%m-%d-%H%M%S"
```

出力先: `newsletters/pickup/YYYY-MM-DD-HHmmss.md`

### 6. Notion へ保存

生成したピックアップを Notion DB「UX Developer newsletter」に **1ピックアップ=1ページ** で保存する。
**`notion-cli` スキルの手順に従うこと。**

**重要（公開リポジトリ対策）**: このリポジトリは公開のため、Notion の DB ID をこのファイルや他のコミット対象ファイルに直書きしない。ID は `.env`（gitignore 済み）から読む:

```bash
# .env から読み込む
NOTION_PICKUP_DATA_SOURCE_ID=$(grep '^NOTION_PICKUP_DATA_SOURCE_ID=' .env | cut -d= -f2)
NOTION_PICKUP_DATABASE_ID=$(grep '^NOTION_PICKUP_DATABASE_ID=' .env | cut -d= -f2)
```

`.env` に該当キーが無い場合は Notion 保存をスキップし、その旨を完了報告に記載する（ファイル生成・コミットは通常どおり行う）。

**ページのプロパティ**（生成した Markdown から抽出してマッピング）:

| プロパティ | 型 | 値 |
|-----------|-----|-----|
| `Name` | title | 1行目の見出し（`# ` を除いたタイトル全体） |
| `作成日` | date | `**作成日**:` の値 |
| `対象期間` | rich_text | `**対象期間**:` の値 |
| `記事数` | number | 本文中の `## [...]` 記事見出しの数 |

**本文**: ピックアップ Markdown 全体を Notion ブロックに変換して入れる。
変換は `notion-cli` スキルの `references/markdown-conversion.md`（quote→callout・mermaid 改行の後処理）に従う。children は1リクエスト最大100ブロックのため、超える場合は分割して PATCH する。

`parent` は `{"type": "database_id", "database_id": "$NOTION_PICKUP_DATABASE_ID"}` を指定する。

### 7. 完了報告

- 作成ファイルのパス
- 対象ニュースレター数と選定記事数
- 選定記事のタイトル一覧
- Notion ページの URL（保存した場合）／スキップ理由（しなかった場合）

### 英語表現の扱い

原文が英語の記事で以下に該当するものは英語のまま記載:

- **UIラベル・ボタン名** — 読者が実際のUIと照合できるように
  - `"Back to YouTube"` → 訳さない
- **著者の固有表現・比喩** — 元のニュアンスを保つ。わかりにくい場合は（）で補足
  - `"man-in-the-middle attack"（中間者攻撃）`
- **概念名・造語** — 記事が定義・提唱している固有名
  - `"context collapse" とは〜を指す`

一般的な技術用語（フィードバックループ、オプトイン等）やパラフレーズは日本語でOK。

# ニュースレター自動作成（非対話版）

このコマンドは `/create-newsletter` の非対話版です。
ユーザー確認なしで自動的にニュースレターを作成し、PRとして提出します。

## 処理手順

### 0. 対象日付の決定

**引数**: $ARGUMENTS（オプション: 対象の日付フォルダ名 例: `2026-01-20`）

1. **引数がある場合**: 指定された日付フォルダを使用
2. **引数がない場合**: 最新の日付フォルダを自動検出
   ```bash
   ls -d articles/[0-9][0-9][0-9][0-9]-[0-9][0-9]-[0-9][0-9] 2>/dev/null | sort -r | head -1
   ```

3. **生成済みチェック**: 対象日付のニュースレターが既に存在するか確認
   ```bash
   ls newsletters/${TARGET_DATE}-*.md 2>/dev/null
   ```

4. **生成済みの場合**: **スキップして終了**（再生成しない）
   - 「既に YYYY-MM-DD のニュースレターが存在します。処理をスキップします。」と報告

### 1. 記事一覧の取得

`articles/YYYY-MM-DD/` ディレクトリ内の記事を検索し、各記事のタイトル・カテゴリ・publishedDateを読み取ります。

**記事がない場合**: エラーメッセージを表示して終了

### 2. 記事選定（自動）

- **15件以下**: すべての記事を詳細掲載
- **16件以上**: 以下の基準で品質の高い15件を**自動選定**
  - 内容の充実度（本文が十分にある記事を優先）
  - トピックの多様性（カテゴリが偏らないように）
  - 実用性・学びの深さ
  - 著名な著者・信頼性の高いソース

### 3. 記事の要約生成

選択された各記事について：

1. **記事本文を読み込む**
2. **3行まとめを生成**
3. **詳細解説を生成**（充実した内容で）
   - 記事の背景・文脈を説明
   - 技術的なポイント、アーキテクチャ、実装の詳細を解説
   - **UXエンジニアリングの視点で解釈を加える**
   - 記事の限界点や注意点があれば言及
   - 関連するトピックや発展的な内容への言及

### 4. ニュースレター生成

以下のフォーマットでMarkdownファイルを生成：

```markdown
# ニュースレター

**発行日**: YYYY-MM-DD

---

## ハイライト

### [記事タイトル](元記事URL)

> **出典**: フィード名 | **公開日**: YYYY-MM-DD | **カテゴリ**: xxx

**3行まとめ**
- ポイント1
- ポイント2
- ポイント3

**詳細解説**

[充実した解説文]

---

（詳細掲載記事ごとに繰り返し）

---

## その他の記事

- [記事タイトル](元記事URL) - カテゴリ / フィード名
- ...

---
```

### 5. ファイル出力

- **出力先**: `newsletters/YYYY-MM-DD-HHmmss.md`

```bash
date "+%Y-%m-%d-%H%M%S"
```

### 6. コミットとプッシュ

```bash
git add newsletters/YYYY-MM-DD-HHmmss.md
git commit -m "docs: Add newsletter for YYYY-MM-DD"
git push origin master
```

### 7. 完了報告

- 作成したファイルのパス
- 含まれる記事数
- 送信結果

## 文体・表記ルール

**必ず `ai/docs/style-guide.md` を読み込み、スタイルガイドに従って文章を生成すること。**

## 注意事項

- 記事が存在しない場合はエラー終了
- 既存のニュースレターがある場合はスキップ
- 要約は原文の意図を損なわないよう正確性を重視
- 技術用語は可能な限り日本語で解説
- 記事のカテゴリで絞り込まない（全カテゴリ対象）
- 詳細解説は充実させる（単なる要約ではなく解釈・考察を加える）

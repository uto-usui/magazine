# 記事キュレーション

このコマンドは、過去のニュースレター（`newsletters/`）から指定期間の記事をピックアップし、UXエンジニアや読者が特に興味を持ちそうな記事を選定してまとめます。

## 引数

**$ARGUMENTS**: 対象期間を自然言語で指定

例:
- `今週` - 直近7日間のニュースレター
- `1月15日から20日` - 指定した日付範囲
- `最新3回分` - 直近3つのニュースレター
- `1月` - 2026年1月全体
- `先週` - 7〜14日前
- 引数なし - 直近1週間をデフォルトとする

## 処理手順

### 1. 対象ニュースレターの特定

1. **ニュースレター一覧を取得**
   ```bash
   ls -1 newsletters/[0-9]*.md 2>/dev/null | sort -r
   ```

2. **引数を解釈して日付範囲を決定**
   - `$ARGUMENTS` が指定されている場合、自然言語を解釈して日付範囲に変換
   - 未指定の場合は直近2週間をデフォルトとする
   - ニュースレターのファイル名（`YYYY-MM-DD-HHmmss.md`）から日付を抽出して照合

3. **対象ファイルを確定**
   - 日付範囲内のニュースレターファイルをリストアップ
   - 対象が0件の場合はエラーメッセージを表示して終了

### 2. 記事の抽出

対象ニュースレターから全記事を抽出：

1. **各ニュースレターファイルを読み込む**（Readツール）

2. **記事情報を抽出**（正規表現またはマークダウン解析）
   - タイトル（`### [タイトル](URL)` 形式）
   - 出典・公開日・カテゴリ（`> **出典**: ... | **公開日**: ... | **カテゴリ**: ...`）
   - 3行まとめ
   - 詳細解説

3. **記事リストを作成**
   - 重複チェック（同じURLの記事は除外）
   - 元のニュースレター日付を記録

### 3. 記事の選定（Claudeによる自動選定）

抽出した記事から、以下の基準でUXエンジニアが特に興味を持ちそうな記事を選定：

**選定基準**:
- **実践的価値**: 実務にすぐ活かせる知見や手法が含まれている
- **技術的深さ**: 単なるニュースではなく、技術的な洞察がある
- **UXエンジニアリング視点**: デザインとエンジニアリングの橋渡しや、それぞれに関連
- **トレンド性**: 業界で注目されているトピック
- **独自性**: 他では得られない視点や情報

**外すもの**:
- 風刺・ジョーク系の記事 → 面白いが実務に活かしにくい
- 内容が薄い記事（有料部分が取得できなかった等）→ 読者に提供できる価値が少ない
- ニッチすぎる記事 → UXエンジニアより別の職種向け

**選定数**:
- 抽出記事が10件以下: 全て選定
- 11件以上: 品質の高い7〜10件を選定

### 4. キュレーション記事の生成

#### 4.1. 編集テーマを決める

選定した記事を俯瞰し、全体を貫くテーマを見つける。例：
- 「AI時代にUXエンジニアはどう働くか」
- 「パフォーマンスと体験の両立」
- 「見えない仕事の価値」

テーマは無理に作らなくてもよいが、あると記事間のつながりが生まれる。

#### 4.2. シリーズとしての視点

このピックアップはシリーズとして継続する。過去の号との関連を意識する：

- 以前紹介した記事と関連するテーマがあれば言及する（「以前の〇〇とも通じる」）
- 同じテーマが続いている場合は、その流れを意識する（「このテーマは最近よく出てくる」）
- 過去のピックアップは `newsletters/pickup/` にある

初回や過去との関連がない場合は無理に言及しなくてよい。

#### 4.3. 記事の並び順

並び順にも意図を持つ：
- 冒頭で提示した問いに関連する記事を最初と最後に配置
- 技術記事を間に挟んでバランスを取る
- 関連する記事は近くに配置

#### 4.4. 出力フォーマット

```markdown
# [期間を表すタイトル] ピックアップ

**作成日**: YYYY-MM-DD
**対象期間**: [解釈した期間を自然な日本語で]

---

[冒頭の導入文：2〜3文程度]

---

### [記事タイトル](元記事URL)

> **出典**: フィード名 | **公開日**: YYYY-MM-DD | **カテゴリ**: xxx

- ポイント1
- ポイント2
- ポイント3

[元のニュースレターの詳細解説をベースに、読み物として自然な文章で]

> **編集部より**: [編集者としてのコメント]

---

（選定記事ごとに繰り返し）

[締めの文章：冒頭の問いを回収しつつ、具体例を含め、季節感で終わる]
```

#### 4.5. 冒頭の導入文

**書くこと**:
- 今回の記事に共通するテーマや傾向を軽く伝える
- 読者を記事に誘い込むフック

**書かないこと**:
- 数字（何号分、何記事から何記事を選んだ等）→ 裏側の話なので不要
- 「3つの柱で構成しています」のような説明 → 自分が書いた記事みたいになる
- 押しつけがましい表現

**トーン**:
- 淡々と、でも温かみのある感じ
- 「やはり」「〜でした」のように少し引いた視点
- 週番号表記（例：202601W3）を使ってもよい

**例**:
```
202601W3の記事は、やはりAIの話題が多めでした。仕様書の書き方、デザイナーの役割の変化、ユーザーフィードバックの活かし方。眺めていると「AIと一緒に働くって、結局どういうことなんだろう」という問いが出てきます。GSAPやCSS、アクセシビリティの話も。
```

#### 4.6. 編集部よりのコメント

**書くこと**（以下のいずれか）:
- 記事に書かれていない視点を足す（限界、前提条件、別の角度からの解釈）
- 他の記事や概念との接続（「今回の〇〇とも通じる」「〇〇を知っていると深まる」）
- ポジティブな好み（「個人的には〇〇が好き」「これはよくやっている」）

**書かないこと**:
- 「〜な人におすすめです」「〜に役立ちます」→ 誰でも書けるラベル付けなので不要
- 読者への直接的な問いかけ（「あなたはどう思いますか？」等）→ メタ的すぎる
- 否定的な評価や炎上リスクのある表現

**例**:
```
> **編集部より**: 「Always / Ask first / Never」の境界設計は、AIに限らずチームメンバーへの権限委譲でも使えるフレームワーク。境界を書くこと自体がAIへの信頼度の可視化になっているのが面白い。
```

```
> **編集部より**: 今回の「Designers as agent orchestrators」とも通じる話で、AIが台頭するほど「曖昧さを扱う」見えにくい仕事の価値が上がる。評価されにくいからこそ、自分で言語化しておく意味がある。
```

```
> **編集部より**: 物理演算をScrollTriggerで表示領域内のみ実行する最適化、こういう地味な配慮がパフォーマンスとリッチさの両立に効く。個人的には「目が怒る」インタラクションが好き。
```

#### 4.7. 締めの文章

**書くこと**:
- 冒頭で提示した問いを回収する
- 今回の記事から具体的な内容を含める（抽象論だけにしない）
- 時勢に合わせたひとこと（後述）
- 「また来週」的な軽い挨拶

**時勢のネタの考え方**:

季節、その日、その週、最近の出来事など、読者と共有できる「今」の感覚を入れる。自分で考えて選ぶこと。例をそのまま使わない。

アイデアの方向性：
- 季節・天気（寒い、暑い、梅雨、花粉など）
- 今日は何の日（検索して面白いものがあれば）
- その週の出来事（技術系のカンファレンス、リリースなど）
- 連休・祝日の前後
- 年度の節目（年始、年度末、四半期など）

**注意**: 政治・宗教・社会問題など、示唆的で炎上リスクのある話題は避ける。あくまで軽く、共感できる範囲で。

**トーン**:
- 前向き（「仕方ない」「しかない」等の消極的表現はNG）
- 押しつけがましくない
- 軽く終わる（長々と書かない）

**タイトル例**:
- 「今週のピックアップ」
- 「1月後半のピックアップ」
- 「直近2週間のピックアップ」

### 5. ファイル出力

生成したキュレーション記事を保存：

- **出力先**: `newsletters/pickup/YYYY-MM-DD-HHmmss.md`
- YYYY-MM-DD: 現在の日付
- HHmmss: 現在時刻（重複防止）

```bash
# 現在日時を取得してファイル名を生成
date "+%Y-%m-%d-%H%M%S"
```

### 6. 完了報告

- 作成したファイルのパスを報告
- 対象ニュースレター数と選定記事数を報告
- 選定した記事のタイトル一覧を表示

## 使用例

```
/curate-articles 今週
→ 直近7日間のニュースレターから記事をキュレーション

/curate-articles 1月15日から20日
→ 2026-01-15 〜 2026-01-20 の記事をキュレーション

/curate-articles 最新3回分
→ 直近3つのニュースレターから記事をキュレーション

/curate-articles
→ デフォルトで直近2週間の記事をキュレーション
```

## 文体・表記ルール

**必ず `ai/docs/style-guide.md` を読み込み、スタイルガイドに従って文章を生成すること。**

主なルール:
- 漢字の開き・閉じ（「こと」「もの」「とき」など）
- NGワード・禁止表現（「革命的」「必見」「〜すべき」など）
- 冗長表現の回避（「〜することができます」→「〜できます」）
- 文体・トーンの統一

## 注意事項

- 対象期間にニュースレターがない場合はエラーメッセージを表示
- 重複記事（同じURL）は自動的に除外
- 元のニュースレターの解説をベースにしつつ、「編集部より」で独自の視点を加える
- 冒頭と締めで問いを共有し、記事全体に一貫性を持たせる
- 読み物として自然な流れを意識する
